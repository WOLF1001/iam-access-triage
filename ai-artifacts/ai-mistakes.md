Журнал реальних помилок, знайдених при прогоні `run_demo.py --all` і тестах.

| # | Що AI-згенерований код/правило робили | Як виявлено | Виправлення |
|---|---|---|---|
| 1 | Regex `зник` для «пропав доступ» матчився всередині слова «показ**ник**ами» → запит на доступ до фін. показників BM класифікувався як діагностика входу | ручна перевірка `full_run.md`, #57 | межа слова `\bзник` |
| 2 | Regex `ключ` (API-ключ) матчився в «під**ключ**итись» → «можеш все видати, що у ліда було» класифікувалось як запит API-ключа | `output.md`, #46 | `\bключ` |
| 3 | Okta сприймалась як цільовий app у «через okta не пускає» / «доступ через okta до композитів» → бот «знав» app, хоча ціль (композит) не в каталозі | #73 давав APPROVAL замість NEED_INFO | okta/hris = context-only apps; ціль невідома → `unknown_app` |
| 4 | Read-only діагностика без знахідок повертала AUTO_RESOLVE («перевірив, усе ок»), хоча нічого не вирішено | `full_run.md`: #1, #3, #15 в AUTO | `diagnostic_inconclusive` → NEED_INFO |
| 5 | Багатоінтентний «доступ до vpn + інструкція» → друга частина без контексту падала в kb_gap → HUMAN | #91 | підзапит без app успадковує контекст із сусіднього |
| 6 | «питання по ліцензуванню coda — скільки коштує» маршрутизувалось у DOCS зі статтею про Coda↔MCP (нерелевантна) | #72 | ціни/знижки → REROUTE procurement |
| 7 | **Multi-sub laundering (critical):** pipeline рахує regex-сигнали по `sub.summary`, який пише LLM. LLM розбиває «адмінку в 1password, всі vault-и» на «доступ до vpn» + «дякую» → AUTO. Золоте правило 2 задеклароване, але не виконане | adversarial-тест з фейковою LLM, що повертає **2** підзапити (сесія 2). 132 початкові тести мали лише 1 підзапит: сліпа зона коду й тестів збіглась | GAP-1 → закрито 2026-10-07 (ADR-010): summary довіряється лише якщо дослівно з тексту + підлога з повного тексту |
| 8 | `app_mentions` від LLM не звіряються з текстом (хоча промпт вимагає «дослівно»): `["vpn"]` для запиту про tableau → AUTO на чужу групу | той самий adversarial-тест | GAP-2 → закрито: незаземлені згадки відкидаються, порядок app — за текстом, AUTO лише для однієї entitlement |
| 9 | Апрув не прив'язаний до subject/app, `approval_ttl_hours: 72` оголошений, але ніде не застосовується | мутація моку approvals у тесті | GAP-3 → закрито: апрув звіряється з subject/app, вікно `resend_max_age_days: 30` |
| 10 | Детектори обходяться homoglyph (латинська «a») і zero-width | тест на обхід | GAP-4 → закрито: `normalize()` (NFKC, без Cf, latin→cyrillic у змішаних словах) |
| 11 | Немонотонність: «лід в курсі» знижує #99 з HUMAN до APPROVAL, бо kb_gap перевіряється лише для DOCS | metamorphic-тест по всіх 108 | GAP-5 → закрито: kb_gap від базового маршруту типу |
| 12 | Мій власний тест (сесія 2) вимагав `risk_tier: low` для всіх birthright-apps → упав на Okta/1Password/GWS. Хибне припущення: birthright = «базовий акаунт є в усіх», а межа AUTO — allowlist груп бота | тест упав на реальному каталозі | тест переписано: перевіряється allowlist груп бота |
| 13 | Згенерований мною n8n-воркфлоу (сесія 2) лишав дефолтне збереження даних виконань → сирий текст Slack з секретом (#32, тред з `sk-ant-…`) осідав у БД n8n **до** redaction у triage-сервісі. Золоте правило 6 виконувалось у сервісі, але не в оркестраторі | канарейковий тест: `grep` по `database.sqlite-wal` у контейнері після прогону #32 | `saveData*Execution: none` у settings воркфлоу + `EXECUTIONS_DATA_SAVE_*` в env; повторний тест — нові виконання не зберігаються.
