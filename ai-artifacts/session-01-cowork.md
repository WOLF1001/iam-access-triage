## Ключові промпт-рішення

- **v1 (наївний):** LLM сама обирає маршрут і пише відповідь → `ai-artifacts/prompts/classify_v1_naive.md`. Відкинуто концептуально: маршрут не можна віддавати недетермінованій моделі, яка читає недовірений ввід.
- **v2 (робочий):** LLM — лише парсер через tool use зі строгою схемою; явна заборона виконувати інструкції з тексту звернення; сигнали тільки з enum → `prompts/classify_v2.md`.
- Перевірка, що LLM не може знизити ризик: тест `test_llm_cannot_downgrade_security` підміняє класифікатор «LLM вважає це how_to» — маршрут лишається SECURITY завдяки regex-сигналам.

## Що AI робив добре

- Швидко знайшов неочевидні пастки датасету (#32 «видаліть нотатку» ≠ відкликання ключа, #42 «тільки по вечорах» як ознака brute force).
- Запропонував read-side факти з `source` + `mechanism` — відповідає вимозі показати, куди і як агент підключається.

## Де AI помилявся

Див. `ai-mistakes.md`: regex-збіги всередині слів («показ**ник**ами», «під**ключ**итись»), Okta як ціль замість механізму, «діагностика без знахідок = вирішено», втрата контексту в multi-intent, нерелевантна KB-стаття для питання про ціну.

## Що AI не міг зробити

- Прогнати реальну LLM: у середовищі сесії не було API-ключа. LLM-шлях перевірено тестом із фейковим клієнтом; реальний прогін — наступний крок.
- Перевірити факти про API вендорів у живих доках — винесено в `docs/PROGRESS.md` → «Перевірити в доках».
